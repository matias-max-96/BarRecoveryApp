4) Atributos técnicos dinámicos 

Aquí dejamos el diseño fino.

<<<<<------------------->>>>>
   BarAttributeDefinitions
<<<<<------------------->>>>>
Define qué atributos existen en el sistema.
Id
Code
Name
DataType
Unit
IsRequired
IsActive
AppliesToBarTypeId (nullable)
AppliesToPlantId (nullable)
DisplayOrder
CreatedAtUtc
UpdatedAtUtc


Significado de los campos clave
DataType
Permite definir el tipo de dato:

Text
Number
Decimal
Integer
Date
Boolean

Unit
Ejemplos:

mm
cm
kg
°
m

AppliesToBarTypeId
Si tiene valor, el atributo aplica a un tipo concreto.
Ejemplo:

“Ángulo especial” solo para barras tipo MAPA.

AppliesToPlantId
Si tiene valor, el atributo aplica a una planta concreta.
Ejemplo:

“Peso nominal cliente interno” solo para planta ANA.

Si ambos son null
El atributo aplica a todas las barras.

<<<<<------------>>>>>
   BarAttributeValues
<<<<<------------>>>>>
Guarda el valor real de cada atributo en cada barra.
Campos:
Id
BarId
AttributeDefinitionId
ValueText
ValueNumber
ValueDate
ValueBool
UpdatedAtUtc


Regla práctica de uso

El administrador crea la definición del atributo.
Control de calidad ingresa el valor del atributo en la barra cuando corresponda.
Recuperación no necesita trabajar con estos atributos.


5) Separación definitiva entre Recuperación y Calidad

Esto también lo dejamos completamente cerrado.

<<<<<------------>>>>>
     Recuperación
<<<<<------------>>>>>
El operario/soldador:
selecciona su nombre
ingresa su pin
selecciona la barra
registra actividad
registra insumos
añade observación
guarda

Recuperación NO decide:

si la barra quedó buena
si se envía
si se da de baja
si sigue recuperable

<<<<<------------>>>>>
       Calidad
<<<<<------------>>>>>
Control de calidad:
busca la barra
consulta historial de recuperaciones
ve atributos técnicos definidos por administrador
rellena valores técnicos
registra inspección
decide:

recuperable
no recuperable
dada de baja
aprobada para envío



Esto deja totalmente clara la responsabilidad de cada rol.

6) Regla adicional nueva que acabas de definir
Voy a dejarla como regla formal porque merece estar documentada:
Regla 6 — Extensibilidad de catálogos maestros
El sistema debe permitir agregar, modificar y desactivar:

plantas
tipos de barra
actividades
insumos
atributos técnicos

sin necesidad de cambiar el código fuente ni la estructura base del proceso operativo.
Esta regla es muy importante porque te protege frente a crecimiento real del negocio.

8) Validaciones recomendadas
En administración

No permitir duplicar Code en plantas
No permitir duplicar Code en tipos de barra
No permitir duplicar Code en atributos
Permitir desactivar, no borrar físicamente por defecto

En atributos

Si un atributo es IsRequired = true, Control de Calidad debe completarlo antes de cerrar inspección
Si DataType = Number, no aceptar texto
Si DataType = Boolean, ofrecer switch o checkbox

En barras

Toda barra debe tener:

identificador
planta
tipo de barra



Nunca se debe crear una barra sin esos tres datos.
